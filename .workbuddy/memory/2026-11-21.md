## 修复移除刷新按钮后的顶部空白（2026-11-21）
- 现象：删除刷新按钮后，仅靠刷新按钮作为唯一操作的页面（黄金行情/收支分析/任务管理/基金收益等）顶部残留 38px 空白。
- 根因：`PageHeader/index.vue` 只渲染返回按钮 + `.pc-page-actions` 插槽；删掉刷新按钮后 header 变空。原先靠 business.css 的 `.pc-page-header:not(:has(> .el-button, .pc-page-actions > *)){display:none}` 隐藏空行，但该 `:has()` 规则在实际渲染中未生效，空行仍占 `min-height:38px`。
- 修复：在 PageHeader 组件内用 `useSlots()` + computed `hasSlotContent`（渲染一次插槽并检查有效 VNode：元素/组件或非空白文本才算内容，注释/空白忽略）得到 `showHeader`，用 `v-show` 控制整行。用 v-show 而非 v-if 以保留 `.pc-page-actions` DOM 供 FloatingAddButton Teleport。覆盖 14 个空 `#right` 插槽页面。
- 坑：`Symbol.for('v-txt')/('v-cmt')` 在生产构建不可靠（Symbol 描述变 undefined），改用 `typeof node.type !== 'symbol'` 判断元素/组件节点。
- 验证：pnpm build、pnpm test（22）、pnpm test:e2e（9/9）全通过。

## 修复 PageHeader 空插槽判断回归导致的顶部留白（2026-11-21）
- 用户真实诉求：`/finance/trend` 页顶部留白（上一轮误做成整页重设计）。根因在 `PageHeader/index.vue` 的 `hasSlotContent`。
- 回归点：之前把文本/注释判断改成 `typeof node.type !== 'symbol'` 后，落到一个缺陷分支 `children 为 string && trim 非空`；v-if=false 生成的注释节点 children 恰是字符串 `"v-if"`，被误判为有效内容 → showHeader=true → 空 header 显示成一行留白。资产趋势页 `#right` 是 `<CommonSelect v-if="showFamilySwitch">`，单用户时必现。
- 修复：抽出纯函数 `pc/src/business/utils/slotContent.ts` 的 `hasRenderableSlotContent`，用 Vue 导出的 `Comment`/`Text` 符号常量精确区分（模块级引用，生产构建可靠，优于不可靠的 `Symbol.for('v-cmt')` 字符串）：注释节点恒不算内容；文本节点需 trim 非空；元素/组件恒算内容。PageHeader 改为调用该函数。
- 坑：不能只看 children 是否非空（注释节点 children="v-if" 会误判）；纯文本插槽要保留，不能一刀切排除所有 symbol 节点。
- 验证：新增 `tests/slotContent.test.ts`（4 例）；pnpm build、pnpm test（26）、pnpm test:e2e（9/9）全通过。
