## PC 端功能优化（2026-11-10 晚）
- **路由级容错**（router/index.ts）：`router.onError` 三分支——chunk 加载失败（发版 404）整页刷新一次（sessionStorage `pc-chunk-reloaded` 防循环，afterEach 清标记）；应用内导航组件 setup 失败（原先静默回滚用户以为"没反应"）→ ElMessage「页面加载失败」；初始导航直接打开崩溃页（原先整站白屏）→ `router.replace('/unavailable')` 兜底。onError 内 `console.error('[Life Hub] 路由导航失败')`。
- **页面级错误边界**（AdminLayout.vue）：`onErrorCaptured` 返回 false + `pageCrashed/pageRenderKey`，崩溃时显示 `.page-crash-fallback` 卡片（TriangleAlert+重试按钮，重试=key 递增重挂 RouterView），替代整页白屏；main.css 有配套样式。
- **主题切换入口**：useTheme 此前从未被任何组件使用——AdminLayout 顶栏新增 `.topbar-actions`（margin-left:auto）Sun/Moon 切换按钮。index.html 加内联预应用脚本（同 theme.ts 逻辑）解决暗色冷启动白闪（FOUC）。
- **session TTL**（stores/session.ts）：`SESSION_TTL_MS=60s`+loadedAt，路由守卫从 `loadSession(true)`（每导航必请求）改 `loadSession()`（TTL 内走缓存）；invalidatePermissions/clearSession 重置 loadedAt；401/403 分支也写 loadedAt 防止 denied 态反复打接口。实测 3 次应用内导航 0 次 session 请求。can() 顺带加固 `permissions?.includes`。
- **main.ts**：加 `app.config.errorHandler`（console.error，布局外错误兜底可查日志）。
- 坑（再次确认）：Playwright mock 规则**后注册者优先**——通配规则必须先注册、session 精确规则最后注册；顺序错了 session 被劫持成无 permissions 数据，守卫 can() 抛 TypeError（正好演示了新 onError 兜底生效：跳 /unavailable 而非白屏）。

## /finance/trend 渲染崩溃修复（2026-11-10 晚）
- 用户报 /finance/trend「页面渲染发生错误」（即 AdminLayout 错误边界卡片）。根因：**美化和重写 business.css 令牌块时丢了一批图表 token**（--color-chart-axis-strong/brand-area-start/brand-area-end/gold/gold-area-start/gold-area-end/tooltip-bg/tooltip-border/tooltip-text），而 InvestmentTrendPage 的 chartOption 用**裸 getPropertyValue** 读这些 token → 空字符串传给 echarts 渐变 `addColorStop('')` → SyntaxError → 页面崩。共 7 个文件消费这批 token（trend/analysis/dividend-strategy/investment-detail/gold-price/stock-screener/photography-overview），其他页因走 readChartToken（带 fallback）幸免。
- 修复三层：① business.css :root 补齐 9 个 token（值对齐 web/src/styles/base.css，能走 el 变量的走 el 变量自动随暗色切换）；② trend 页 chartOption 全部改 readChartToken 带 fallback；③ trendMerge.ts 所有 `result.xxx.forEach` 加 `?? []` 防御（消除「接口形状异常→英文 TypeError 裸露在 el-alert」一类问题），hasTrendPoints 加 `trendPoints?.length`。
- 复现套路：mock 响应用真实形状（family overview {hasFamily,members}、trend 全字段、snapshot accounts 数组）+ **Playwright route 注册顺序（通配在前、精确在后）**——顺序错了会被通配规则劫持，出现假崩溃假象，排查时先查 mock 顺序。
- 定位技巧：报错被页面 catch 吞掉看不到堆栈时，可在浏览器里 `import('/src/.../trendMerge.ts')` 逐函数喂数据拿堆栈（vite dev 下可用）。
- 验证：真实形状数据 → 图表 canvas 渲染、无报错；空数据 → 友好「暂无昨日账户快照」；pnpm test 16/16、build 通过。

- 用户报 /finance/trend「所有账户与今日一致」一直显示。根因：PC 端移植 H5 时展示逻辑错位——`applyYesterdaySnapshots` 只要快照返回了账户就无条件把 snapshotError 赋成「所有账户与今日一致」，模板里 `el-alert type="error" v-if="snapshotError"` 无条件渲染 → 恒显示红色错误告警。H5 原语义是**空态占位**（仅所有账户变动为 0、表格无内容时显示）。修复：改为仅「有账户但全部 |changeAmount|==0」时提示，alert type 改 info；有变动账户时表格已展示对比不重复提示。build 通过。
