# 项目长期约定（life-hub + web）

## 前端（vue3-ts-app）硬性规范
- **rem 适配陷阱**：`utils/rem.ts` 把 html.fontSize 设为动态大值（视口/375×37.5 ≈ 39px），postcss-pxtorem（rootValue 37.5，minPixelValue 2）把 px 转 rem。body 未设 font-size → **任何依赖继承字号的元素会直接拿到 ~39px**。新增文本元素必须显式设 `font-size: var(--font-size-*)` token，或确保页面根有继承基准字号（`.market-page` 与独立的 `.detail-page` 都已各自设 14px 基准；详情页 `/finance/global-market/detail/:kind/:code` 是独立顶层路由，不在 market 外壳内）。
- **grid 溢出陷阱**：页面级 grid 的轨道默认 min-width:auto，nowrap 表格/文本的 min-content 会沿 grid 链条把整页撑出横向滚动。容纳宽内容的 grid 必须加 `> * { min-width: 0 }`，宽表格交给卡片内 `overflow-x: auto` 的包裹层滚动。
- design token 全部在 `src/styles/base.css`：涨=红 `--color-danger`、跌=绿 `--color-success`、金色点缀 `--color-chart-gold`；**字号 token 只有 11/12/13/14/16/18/20/24/26/28/30/36/38（15/17 等不存在，var 引用空值会回退继承 43px！）**；间距 `--space-2~96`（18/30 等不存在，28 存在）、圆角 `--radius-8~36`；注意 `--space-18` 不存在。
- API：`financeRequest` 实例无路径前缀，路径须写全（如 `/api/finance/market/...`）；行情行数据用中文键 Map 保持与后端契约一致。

## 后端（spring-cloud-bookkeeping）
- **服务架构（2026-10-30 行情拆分后）**：三服务 auth-service(8081, 独立认证中心) + app-service(8082, 全部业务；原 finance-service，包 `com.example.app`/主类 `AppServiceApplication`) + market-service(8083, 行情中心，包 `com.example.market`，/api/market/*，JWT 认证与 app-service 同套：同 JWT_SECRET/DB_PASSWORD，UserStatusChecker 查同一 MySQL；依赖 web+validation+spring-boot-starter-jdbc+mysql-connector-j)。tool 代码在 `com.example.tool` 包（路由前缀 `/api/tools/*`），food 在 `com.example.food` 包（路由 `/api/tools/food/*`），均并入 app-service。选股引擎经 MarketClient → /api/internal/market/kline（日K）+ /api/internal/market/stock-list（全市场清单，新浪 hs_a 含北交所，30min 缓存）调行情中心，**A股选股外部数据 100% 走 market-service，app-service 零东财依赖**。前端行情接口走 marketRequest + /market-api 代理 → 8083。跨服务 Client（FinanceClient/ToolServiceClient）已是同 JVM 本地调用；`/api/internal/**` + X-Internal-Key 保留为兼容入口。前端 `/tool-api`、`/food-api` 代理 target 都是 8082。
- app-service 端口 8082；JWT_SECRET/DB_PASSWORD 取自 `life-hub/.idea/runConfigurations/AppServiceApplication.xml`（MarketServiceApplication.xml 里也有）。
- 涨跌停接口 `/api/market/limit-up-down` 全量返回列表（与汇总家数一致），前端选股页默认显示 5 条+展开按钮；internal 对照口 `/api/internal/market/limits`（原始键 limit_up/up/down）。
- **金价（2026-10-30 迁移 + 去金投化后）**：整体在 market-service `com.example.market.gold`（对外 `/api/market/gold-prices`，内部 `/api/internal/gold/price|realtime|spot-price|refresh`）；app-service `GoldPriceService` 仅是 `MarketGoldClient` 适配层（签名不变），金账户/资产趋势/投资估值经它取价，`GoldPriceCacheTask` 定时预热调 internal /refresh。前端 `getGoldPrices`/`getRealtimeGoldPrice` 走 marketRequest。**app-service 已无 `/api/finance/gold-prices` 路由**。**数据源：实时主源新浪（`gds_AU9999` 上金所现货9999 + `hf_XAU` 伦敦金，字段 f0最新/f4高/f5低/f6时间/f7昨收/f8开/f12日期/f13名称，GBK）+ 走势主源新浪沪金连续 AU0（getFewMinLine type=1/60 分钟线、getDailyKLine 日K，JSONP `var _=([{d,o,h,l,c}])`，注意 `d` 时空格分隔需 replace 成 T）；金投仅剩首饰金价 8 家（独家数据）+ 作为新浪故障降级源。走势用 AU0 期货连续有 ~0.15% 期现基差（新浪无现货9999历史K线，东财有但用户拒绝）。**
- 前端截图验证套路：playwright-core 用 NODE_PATH 借用 `/Users/luotianxu/WorkBuddy/2026-10-28-15-15-40/daily_stock_analysis/apps/dsa-web/node_modules`（托管 workspace 装 playwright 会被 SIGKILL）；chromium 缓存在 ~/Library/Caches/ms-playwright，launch 用 channel:"chrome"；登录态=自签 JWT（HS256 + JWT_SECRET，claims sub+userId，userId=1）写 access_token cookie + localStorage bookkeeping_current_user。
